# Artifact boundary

`initial_workspace` and attachments are sealed into a validated tar archive by the runner and copied through the workstation gateway, controller, broker, and AF_VSOCK guest agent into `/home/kali/workspace`. The guest validates archive names, types, sizes, duplicates and digest before extraction. The controller sends bounded chunks and verifies the complete SHA-256.

Trusted clients stage an input with authenticated `POST /control/artifacts` on the workstation gateway. The response contains its SHA-256 `artifact_id`. `import_file` accepts that ID and a guest path. `export_file` copies a guest file into the broker's per-attempt, content-addressed store and returns an ID, size and digest. Authenticated `GET /control/artifacts/{artifact_id}` downloads it outside the MCP result. Broker/guest transfers use bounded, verified chunks; the artifact store is deleted with the VM attempt. The agent browser shares the guest filesystem and downloads into `/home/kali/Downloads`. No inter-App file relay or host shared folder is used.
